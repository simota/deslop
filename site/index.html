PASS 01 · CONTENT PERSPECTIVES (CON-01 – CON-08 / CNT-01)

1. 内容パス：4つのテストを通過しない主張は、言い換えず削除する

reference/content.md

各段落のすべての主張を以下の4つのテストにかけます。1つでも落ちた文は、美辞麗句に書き換えるのではなく削除の対象です。根拠のない数値が議論の前提になっている場合は勝手に書き換えず、decisions に記録して著者の判断を仰ぎます。

  • 1. Information (情報テスト / CON-01)：その文を読んだ後、読者が新しく知る事実は何か？「〜が重要です」しかなければ削除する。
  • 2. Substitution (置換テスト / CON-01, CON-07)：主語を別の製品やライブラリに置き換えてもそのまま成り立つ文なら、その対象について何も語っていない。
  • 3. Reader (読者テスト / CON-02, CON-05)：想定読者が目的を果たすために必要か？毎日使う用語の定義や数合わせの一般論は削る。
  • 4. Support (裏づけテスト / CON-03, CNT-01)：文書内の測定値・コード・リンクで裏づけられているか？無出典の「約30%改善」は装飾なら削除、前提なら要出典として報告する。

PASS 02 · STRUCTURAL PERSPECTIVES (STR-01 – STR-16)

2. 構造パス：予告開幕・反復まとめ・機械的な3項目リストを解体する

reference/structure.md

単語単位の正規表現だけでは見抜けない「文書の骨格のクセ」は、16の構造観点の対象です。detect.py（cues.py）が文書の形状から11種類の構造キューを行番号付きで自動抽出し、エージェントの精読箇所をガイドします。

  • STR-01 Announced opening：「本記事では〜を解説します」やタイトルの反復で始まる第1段落を削除し、1文目から本題に入る。
  • STR-02 Closing that restates：「## まとめ」「In conclusion」で本文を繰り返す最終節を削除する。
  • STR-05 / DEN-04 Over-structuring：1つの説明を細切れにした「**ラベル**: 説明」箇条書きを自然な散文に戻す。
  • STR-16 Voice drift：途中で「です・ます」と常体が混ざる文体ブレや表記揺れを著者の voice に統一する。

PASS 03 & 04 · SENTENCES, WORDS & DENSITY (ART / JA / EN / EMO / DEN)

3. 文・語彙・密度パス：チャット残骸とインフレ語彙を根絶する

reference/patterns.md

Wikipedia「Signs of AI writing」、PubMed抄録の過剰語彙研究（Kobak et al. 2025 / Juzek and Ward 2025）、日本語AI文体分析に基づき整備されたルールセットで、残った文の贅肉を落とします。

  • Artifact (ART-01 – ART-09)：「承知しました」「Certainly!」「I hope this helps」「utm_source=chatgpt.com」「oaicite」「[会社名]」等のチャット残骸。引用内を除き免除不可。
  • Japanese Lexical (JA-01 – JA-33)：「〜と言っても過言ではありません」「〜することができます」「シームレス」「単なる〜ではなく」「深掘り」「〜となっております」。
  • English Lexical (EN-01 – EN-27)：delve, tapestry, leverage, seamless, plays a crucial role, isn't just X — it's Y。
  • Density (DEN-01 – DEN-10)：太字密度、ダッシュ密度、感嘆符比率、同じ文末の4連続（〜できます。×4）、文長の変動係数（CV < 0.3）。

DETERMINISTIC RUN CONTRACT

「AIが勝手に事実やコードを書き換える」を許さない8フェーズ実行契約

Claude Code、Codex、Antigravity のどのエージェントから実行しても同じ品質を保証するため、deslop は7つの Python スクリプトで各フェーズの入出力を縛り、中断した実行には status.py が次の手順を示し、最後に contract_check.py が原本スナップショットから再計算して合否を判定します。

PRESERVE_CHECK.PY · FACT IDENTITY ENGINE 原本 (original/) と作業コピー間で1つでも無断の消失・追加があれば Exit 1 で差し戻す5種の事実要素
code_block コードブロック完全不変

フェンス（``` / ~~~）やインデントコード、リスト内コードブロックを SHA-256（先頭12桁）で照合。1文字の変更も許しません。

inline_code インラインコード・識別子

`ttl_seconds` や `--canary-percent` など、行をまたぐコードスパンや引用内の識別子の消失・捏造を検出します。

number 数値・符号・指数・全角数字

-10 → 10 の符号脱落、.5 → 5、10⁻³、全角数字まで厳密に区別。装飾統計を削る場合は preservation に理由が必須です。

url URL・リンク先・参照定義

裸のURL、<https://...>、インラインリンク、参照定義リンク（[id]: target）の完全一致を検証し、勝手に短縮・改変させません。

footnote 脚注の参照と定義のペア

本文中の脚注参照（[^1]）と末尾の定義（[^1]: ...）を別個に検査。定義だけ残して本文の出典参照を消す行為も検出します。

GENRE-AWARE DETECTION

TECHNICAL FAQ

導入前のよくある質問

AI検出器（AI Detector）のスコアを回避するためのツールですか？
いいえ。deslop はAI検出器のスコアを目標とせず、スコアの報告も行いません。また、人間らしさを偽装するために意図的な誤字やスラング、不自然な改行を混ぜることも一切禁止しています。目的は「責任ある人間の著者が署名できる品質の文章にすること」であり、披露義務がある場面でのAI利用隠蔽は明確に拒否します。
書き換え中にコードブロックや設定値、URLが壊れることはありませんか？
preserve_check.py が原文スナップショット（original/）と書き換え後の文書を比較し、数値（符号・小数点・指数・全角数字を含む）、URL、Markdownリンク先、インラインコード、コードブロック、脚注のすべてを照合します。コードブロックは絶対に編集されず、数値やリンクが1つでも無断で消えたり追加されたりした場合は契約検査（contract_check.py）が失敗（Exit 1）します。
Git管理外のファイルや、コミット前の変更があるファイルを上書きしませんか？
直接上書き（in-placeモード）が既定になるのは、すべての対象ファイルが Git で追跡されており、未コミットの変更がない場合だけです。それ以外の場合や、原本を残したい場合は自動的にコピーモード（snapshot.py --copy）で動作し、書き換え結果は実行ディレクトリの <out>/rewritten/ に出力されます。
ファイルを書き換えずに「どこがAIっぽいか」だけ診断できますか？
できます。エージェントに「どこがAIっぽく読めるか診断して」と尋ねれば DETECT フェーズの後に停止し、ファイルを一切変更せずにヒット箇所と構造所見を報告します。また、CLIから make detect TARGET=docs/ または python3 skills/deslop/scripts/detect.py docs/ を単体実行することも可能です。
動作に必要な環境や追加パッケージは何ですか？
Python 3.10 以上の標準ライブラリのみで動作します。pip install や npm install は一切不要です。そのため、make link でシンボリックリンクを作成するだけでどのディレクトリからでも即座に自己完結して動作します。
