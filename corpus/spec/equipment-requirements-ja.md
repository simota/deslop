# 社内備品管理システム 要件定義書

## 1. 文書概要

本書は、社内におけるPC、周辺機器、什器等の備品管理業務を効率化・可視化するための「社内備品管理システム」の要件を定義するものである。

| 項目 | 内容 |
|---|---|
| 対象システム | 社内備品管理システム（Equipment Management System: EMS） |
| バージョン | 1.0.0 (初版) |
| ステータス | ドラフト |
| 作成日 | 2026-11-01 |
| 対象読者 | 開発担当者、総務・情シス部門担当者、プロジェクト関係者 |

---

## 2. 背景と目的

### 2.1 背景
現在、社内の備品管理（PC、モニター、検証端末、事務用品、什器等）は、スプレッドシートへの手入力やメールでの貸出申請によって運用されている。これに伴い、以下の課題が発生している。
- 備品の所在や利用状況がリアルタイムで把握できず、所在不明や紛失が発生している。
- 貸出期限の超過（延滞）に対する自動催促の仕組みがなく、総務担当者の督促業務が負担となっている。
- 年2回の定期棚卸において、現物確認と台帳の突合に多大な工数がかかっている。
- 備品の修理履歴や耐用年数が把握できず、適切な買い替え・更新計画が立てられない。

### 2.2 目的
本システムを導入することにより、以下の達成を目指す。
- 備品情報の一元化とステータス（利用可、貸出中、修理中、廃棄予定等）の可視化。
- モバイル端末やQRコードを活用した貸出・返却および棚卸作業の効率化。
- 返却期限の自動通知による延滞防止および督促業務の削減。
- 備品の利用実績・コストの可視化による調達プロセスの最適化。

---

## 3. システム化の範囲

### 3.1 対象範囲（In Scope）
- 備品台帳の登録・更新・削除・検索機能
- QRコード／バーコードの発行・読み取り機能
- 一般社員向け備品貸出・返却申請および承認ワークフロー
- 管理者向け在庫管理、棚卸支援機能
- 外部連携（Slack通知、Google Workspace/SAML認証）

### 3.2 対象外範囲（Out of Scope）
- 消耗品（文房具やトナー等）の発注・自動補充管理（将来拡張検討）
- 会計システム・固定資産台帳とのリアルタイム自動仕訳連携（CSVエクスポートでの対応とする）
- 備品専用のネイティブモバイルアプリ開発（PWA対応のWebアプリケーションとする）

## 4. ユーザーロールと権限

本システムで定義するユーザーロールおよび権限は以下の通り。

| ロール名 | 想定対象 | 権限範囲 |
|---|---|---|
| システム管理者 | 情シス部門管理者 | システム全般の設定、マスタ管理、全データ閲覧・編集、権限付与、監査ログ閲覧 |
| 備品管理者 | 総務担当者、備品責任者 | 備品台帳の登録・編集・廃棄処理、貸出承認、棚卸管理、アラート通知設定 |
| 一般ユーザー | 全従業員（正社員・契約社員・業務委託） | 備品一覧検索、貸出申請、自己の貸出・返却履歴閲覧、棚卸スキャン参加 |
| 閲覧専用 | 監査役、役員 | 備品台帳および集計ダッシュボードの閲覧（編集不可） |

## 5. 業務フロー概要

### 5.1 備品新規登録フロー
1. 管理者が新品または既存備品をシステムに登録（品名、カテゴリ、シリアル番号、保管場所等）。
2. システムが固有の備品IDを採番し、QRコードラベルを生成。
3. ラベルプリンタでQRコードを印刷し、現物に貼付。
4. ステータスを「利用可能」に設定。

### 5.2 貸出・返却フロー
1. **貸出申請**: 一般ユーザーがPCまたはスマートフォンから備品を検索し、利用期間・利用用途を入力して申請。
2. **承認**: 備品管理者が申請内容を確認し、システム上で承認（即時貸出備品は承認スキップ可）。
3. **引渡・貸出確定**: 利用者が保管場所にて備品のQRコードをスキャンし、貸出処理を完了。ステータスが「貸出中」に遷移。
4. **返却**: 利用者が備品を所定の場所に戻し、QRコードをスキャンして返却完了。
5. **返却確認**: 備品管理者が現物状態（破損等の有無）を確認し、ステータスを「利用可能」に戻す。

### 5.3 定期棚卸フロー
1. 管理者が棚卸イベントを作成（対象カテゴリ・設置場所・期間を指定）。
2. 各部門の担当者または管理者が、スマートフォンのカメラで備品のQRコードを順次スキャン。
3. システムが台帳と照合し、「確認済」「未確認」「所在不一致」を自動分類。
4. 管理者が差異レポートを確認し、紛失・所在変更の確定処理を行う。

## 6. 機能要件

### 6.1 認証・ユーザー管理機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-AUTH-01 | SAML/SSO認証 | Google Workspace / Azure AD (Entra ID) を利用したシングルサインオンに対応すること。 |
| F-AUTH-02 | ロール権限管理 | ユーザーごとに「システム管理者」「備品管理者」「一般ユーザー」「閲覧専用」を割り当てること。 |
| F-AUTH-03 | 所属・組織同期 | SCIM連携またはCSVインポートによる社員・部署情報の自動／手動同期に対応すること。 |

### 6.2 備品台帳・マスタ管理機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-EQUIP-01 | 備品情報登録・編集 | 以下の項目を管理可能とすること：備品ID、品名、カテゴリ、メーカー、型番、シリアルNo、取得日、取得価格、耐用年数、保管場所、管理部署、管理者、ステータス、備考、画像（最大3枚）。 |
| F-EQUIP-02 | 備品一括インポート/エクスポート | CSVまたはExcelファイルによる一括登録、一括更新、全件エクスポートを可能とすること。 |
| F-EQUIP-03 | QRコード発行 | 備品IDを埋め込んだQRコード（SVG/PNG形式）を個別または一括でPDF生成・印刷できること。 |
| F-EQUIP-04 | カテゴリ・場所マスタ管理 | 備品カテゴリ（PC、周辺機器、ディスプレイ、什器、通信機器等）および設置場所（オフィス、フロア、会議室、倉庫等）を階層管理できること。 |
| F-EQUIP-05 | 廃棄・除籍管理 | 破損・老朽化による廃棄申請および承認フロー。廃棄証明書やリサイクル業者の引渡ログを添付可能とすること。 |

### 6.3 貸出・返却管理機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-RENT-01 | 備品検索・空き状況確認 | キーワード、カテゴリ、場所、利用可能期間による備品の高速検索およびカレンダー形式での予約状況確認。 |
| F-RENT-02 | 貸出申請・予約 | 希望利用期間、用途、持ち出し先（社内/社外）を指定して申請できること。事前予約にも対応。 |
| F-RENT-03 | 承認ワークフロー | 申請に対して管理者が承認/却下できること。自動承認設定（消耗型備品や短時間貸出）にも対応。 |
| F-RENT-04 | QRコードによる貸出/返却受付 | スマートフォンカメラで備品ラベルのQRコードをスキャンし、ワンタップで貸出・返却を完了できること。 |
| F-RENT-05 | 延長申請 | 貸出期限前に、利用者がシステムから返却延長申請を行えること（他予約がない場合に限る）。 |
| F-RENT-06 | 延滞検知・アラート | 返却予定日を過ぎた備品を自動検知し、利用者および管理者に通知すること。 |

### 6.4 棚卸管理機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-INV-01 | 棚卸計画作成 | 棚卸の実施期間、対象エリア、対象カテゴリを指定した棚卸セッションの起票。 |
| F-INV-02 | モバイル棚卸スキャン | スマホブラウザのカメラでQRコードを連続読み取りし、検品結果を即座にサーバーへ反映。 |
| F-INV-03 | 差異照合・突合 | 台帳データとスキャン結果を自動突合し、所在不明、未スキャン、場所不一致の一覧を出力。 |
| F-INV-04 | 棚卸完了・台帳反映 | 棚卸結果に基づき、現物所在への台帳一括更新および紛失ステータスへの変更を実行。 |

### 6.5 通知・連携機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-NOTIF-01 | メール通知 | 申請完了、承認完了、却下通知、返却期限前日リマインド、延滞警告メールの送信。 |
| F-NOTIF-02 | Slack/Teams通知 | 申請・承認通知、延滞アラートを社内チャットツール（Webhook / Bot連携）に送信できること。 |

### 6.6 レポート・監査機能
| 機能ID | 機能名 | 詳細・仕様 |
|---|---|---|
| F-REP-01 | 利用状況ダッシュボード | 総備品数、稼働率、延滞件数、修理中件数、部門別貸出比率をグラフで可視化。 |
| F-REP-02 | 監査ログ | ユーザーのログイン履歴、データの作成・更新・削除履歴を操作者・日時とともに記録・検索可能とすること。 |

## 7. 非機能要件

### 7.1 可用性・信頼性
- **稼働率目標**: 99.5%以上（計画メンテナンス時間を除く、平日8:00〜20:00を主運用時間帯とする）。
- **バックアップ**: データベースの自動スナップショットを日次で取得し、過去30日間分を保持。別リージョンへの地理的冗長化を実施。
- **目標復旧時点 (RPO)**: 24時間以内。
- **目標復旧時間 (RTO)**: 4時間以内。

### 7.2 性能・拡張性
- **応答速度**:
  - 一般的な画面表示およびQRコード読み取り照合：2.0秒以内。
  - 備品検索（10,000件のデータを対象としたキーワード検索）：1.0秒以内。
- **同時アクセス数**: ピーク時（棚卸期間、出社集中時間帯）において同時接続50ユーザーを安定して処理可能であること。
- **データ保持件数**: 備品レコード最大50,000件、貸出履歴レコード過去5年分（約500,000件）をパフォーマンス劣化なく保持可能であること。

### 7.3 セキュリティ
- **通信暗号化**: 全通信経路でTLS 1.3以上を必須とし、HTTPSのみを許可。
- **データ暗号化**: 保存データ（データベース、オブジェクトストレージ）のAES-256による暗号化。
- **アクセス制御**: IPアドレス制限（社内ネットワークまたはVPN経由のみアクセス許可、またはIdPの条件付きアクセスで制御）。
- **脆弱性対策**: OWASP Top 10に対応し、クロスサイトスクリプティング（XSS）、SQLインジェクション、CSRF等の脆弱性を排除。
- **セッション管理**: アイドル状態が60分継続した場合の自動ログアウト。

### 7.4 ユーザビリティ・対応端末
- **対応ブラウザ**: Google Chrome、Safari、Microsoft Edge（各最新版）。
- **マルチデバイス対応**: レスポンシブWebデザインとし、PC（1920x1080〜1366x768）、タブレット、スマートフォン（iOS Safari, Android Chrome）で操作可能であること。
- **カメラ連携**: スマートフォンの標準ブラウザから直接背面カメラを起動し、QRコードをスムーズに読み取れること。

## 9. 移行および導入計画

1. **データ準備・クレンジング**: 既存のスプレッドシート台帳の表記揺れ修正、重複削除、シリアルNo確認。
2. **マスタ・データ移行**: CSVインポートによる初期データ投入および整合性検証。
3. **QRコード貼付作業**: 既存備品へのQRコードラベル印刷および現物貼付。
4. **パイロット運用**: 総務・情シス部門内にて1ヶ月間の先行運用を実施し、業務適合性を検証。
5. **全社展開・説明会**: 利用マニュアルの配布および社内向け操作説明会の実施。
