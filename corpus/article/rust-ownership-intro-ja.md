# Rust の所有権と借用入門――値を「持つ」と「借りる」を理解する

Rust を学び始めると、最初につまずきやすいのが「所有権」と「借用」です。ほかの言語では動くように見えるコードが、Rust ではコンパイルエラーになることがあります。

この仕組みは、メモリの解放忘れや、解放済みのメモリへのアクセスなどを防ぐためにあります。まずは「値を誰が管理しているか」と「その値をどう貸し出すか」に注目してみましょう。

## 所有権は、値を管理する責任

Rust の所有権には、基本となる三つのルールがあります。

- 値には、所有者がいる。
- 所有者は、同時に一つだけ。
- 所有者がスコープを抜けると、値は破棄される。

スコープとは、変数を使える範囲のことです。次のコードでは、波括弧 `{}` の内側が `message` のスコープです。

```rust
fn main() {
    {
        let message = String::from("こんにちは");
        println!("{}", message);
    } // message が破棄され、その管理するメモリが解放される
}
```

`String` は、長さを変更できる文字列の型です。文字列データの保存にはヒープ領域を使いますが、上の例では自分で解放処理を書く必要はありません。

所有者である `message` がスコープを抜けると、Rust が後始末を行います。

## 代入すると、所有権が移動することがある

次のコードを見てください。

```rust
fn main() {
    let first = String::from("Rust");
    let second = first;

    println!("{}", second);

    // 次の行を有効にするとコンパイルエラー
    // println!("{}", first);
}
```

`let second = first;` では、文字列全体を複製していません。`first` が持っていた所有権が `second` に移ります。これを**ムーブ（move）**と呼びます。

ムーブ後の `first` は使えません。同じ文字列データを二つの変数がそれぞれ自分のものとして管理し、二重に解放してしまうことを防ぐためです。

独立したコピーが必要なら、明示的に `clone()` を使えます。

```rust
fn main() {
    let first = String::from("Rust");
    let second = first.clone();

    println!("{}", first);
    println!("{}", second);
}
```

この場合は文字列データも複製されるため、両方の変数を使えます。ただし、複製にはメモリ確保やデータのコピーが伴います。コンパイルエラーを消すために、むやみに `clone()` を追加するのは避けたいところです。

## 整数などはコピーされる

一方、整数では次のコードが動きます。

```rust
fn main() {
    let first = 42;
    let second = first;

    println!("{}", first);
    println!("{}", second);
}
```

整数や `bool`、`char` などは、`Copy` という性質を持っています。これらは代入時にコピーされるため、元の変数もそのまま使えます。

まずは、次の違いを覚えておくと読み進めやすくなります。

| 型の例 | 代入した後の扱い |
|---|---|
| `i32`、`bool`、`char` | コピーされ、元の変数も使える |
| `String`、`Vec<T>` | ムーブされ、元の変数は使えなくなる |

なお、`Copy` は単に「サイズが小さい」という意味ではなく、型が持つ性質です。

## 関数に渡すときも、所有権は移動する

ムーブは、変数への代入だけで起こるわけではありません。関数に値を渡すときも同じです。

```rust
fn print_message(message: String) {
    println!("{}", message);
} // message が破棄される

fn main() {
    let text = String::from("こんにちは");
    print_message(text);

    // text は関数にムーブされたため、ここでは使えない
    // println!("{}", text);
}
```

`print_message` は `String` を値として受け取るため、所有権も受け取ります。

しかし、表示するだけなら、呼び出し元から所有権を受け取る必要はなさそうです。そこで使うのが「借用」です。

## 借用すると、所有権を渡さずに値を使える

借用とは、**参照を通して値を使うこと**です。

```rust
fn print_message(message: &str) {
    println!("{}", message);
}

fn main() {
    let text = String::from("こんにちは");

    print_message(&text);

    // 所有権は移動していないので、引き続き使える
    println!("{}", text);
}
```

`&text` は、`text` を借りる参照を作ります。関数はその参照を通して文字列を読みますが、所有者にはなりません。

ここで登場する `&str` は、文字列の一部分または全体を参照する型です。`String` の参照は、必要に応じて `&str` に変換されます。文字列を読むだけの関数では、`&str` を受け取る形がよく使われます。

共有参照である `&T` は、同時に複数作れます。

```rust
fn main() {
    let text = String::from("Rust");

    let first = &text;
    let second = &text;

    println!("{} / {}", first, second);
}
```

通常の `String` の内容は、これらの共有参照を通して変更できません。

## 借りた値を変更するには `&mut`

借用先で値を変更したいときは、**可変参照**である `&mut T` を使います。

```rust
fn add_greeting(message: &mut String) {
    message.push_str("、こんにちは！");
}

fn main() {
    let mut text = String::from("Rust");

    add_greeting(&mut text);

    println!("{}", text); // Rust、こんにちは！
}
```

二つの `mut` に注目してください。

- `let mut text` は、`text` の値を変更できるようにする。
- `&mut text` は、変更するための可変参照を作る。

`&mut String` を受け取った関数は、所有権を受け取らずに、元の文字列を変更できます。

## 共有参照と可変参照には、組み合わせのルールがある

借用では、同じ値へのアクセスが次のどちらかになる必要があります。

- 複数の共有参照 `&T`
- 一つの可変参照 `&mut T`

同じ値について、使用中の共有参照と可変参照を混在させることはできません。

次のコードはコンパイルエラーになります。

```rust
fn main() {
    let mut text = String::from("Rust");

    let reader = &text;
    let writer = &mut text; // エラー

    writer.push_str("!");
    println!("{}", reader);
}
```

`reader` を後で使う予定があるのに、その途中で `writer` を作って変更しようとしているためです。

一方、次の順序なら動きます。

```rust
fn main() {
    let mut text = String::from("Rust");

    let reader = &text;
    println!("{}", reader); // reader の最後の使用

    let writer = &mut text;
    writer.push_str("!");

    println!("{}", text);
}
```

このようなコードでは、Rust は参照が最後に使われる場所までを考慮します。参照を入れた変数が同じスコープに残っていても、借用が終わっていれば次の借用へ進めます。

## 参照先は、参照より長く生きている必要がある

借用には、もう一つ大切な条件があります。参照を使う間は、参照先の値が存在していなければなりません。

次のコードはコンパイルできません。

```rust
fn main() {
    let reference;

    {
        let text = String::from("Rust");
        reference = &text;
    } // text はここで破棄される

    println!("{}", reference); // 参照先が存在しない
}
```

もしこれを許すと、解放済みのメモリを参照してしまいます。Rust は、このような**ダングリング参照**をコンパイル時に防ぎます。

値や参照が有効である期間を「ライフタイム」と呼びます。多くの場面ではコンパイラが関係を推論するため、最初からライフタイム注釈を覚える必要はありません。

まずは「借りたものを使う間は、持ち主がその値を保持している必要がある」と理解しておきましょう。

## 迷ったら、関数が何をするかを考える

関数の引数を設計するときは、その関数に必要な操作から考えると整理できます。

| 関数がしたいこと | 引数の形の例 |
|---|---|
| 文字列を読む | `&str` |
| 呼び出し元の文字列を変更する | `&mut String` |
| 文字列の所有権を受け取る | `String` |

所有権のエラーが出たら、まず「値を渡した後も使おうとしていないか」を確認します。借用のエラーなら、「読むための参照がまだ使われる途中で、変更しようとしていないか」「参照先が先に破棄されていないか」を見てみましょう。

所有権は値を管理する責任、借用はその責任を移さずに値を使う方法です。この二つを区別できるようになると、Rust の関数の引数や、コンパイラのエラーメッセージが少しずつ読みやすくなります。
