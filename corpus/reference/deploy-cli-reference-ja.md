# shipit deploy

指定したアプリケーションを、対象の環境へデプロイします。

## 書式

```
shipit deploy [OPTIONS] <APP>
```

## 説明

`shipit deploy` はアプリケーション `<APP>` のビルド成果物を、指定した環境へリリースします。デプロイは次の順で進みます。

1. 事前チェック（認証、対象環境の状態、デプロイロックの有無）
2. 成果物の取得（`--ref` で指定したリビジョン、または `--image` で指定したイメージ）
3. ロールアウト（`--strategy` に従う）
4. ヘルスチェック
5. 失敗した場合は自動でロールバック（`--no-rollback` を指定した場合を除く）

本番環境（`production`）へデプロイするときは、`--yes` を指定しない限り確認プロンプトが表示されます。

## 引数

| 引数 | 説明 |
|---|---|
| `<APP>` | デプロイするアプリケーション名。`shipit apps list` で確認できます。 |

## オプション

| オプション | 短縮形 | 値 | デフォルト | 説明 |
|---|---|---|---|---|
| `--env` | `-e` | `<ENV>` | `staging` | デプロイ先の環境（`development` / `staging` / `production`）。 |
| `--ref` | `-r` | `<GIT_REF>` | `main` の最新コミット | デプロイするブランチ、タグ、またはコミット SHA。 |
| `--image` | | `<IMAGE>` | なし | ビルド済みのコンテナイメージを直接指定します。`--ref` とは同時に指定できません。 |
| `--strategy` | `-s` | `rolling` \| `blue-green` \| `canary` | `rolling` | ロールアウトの方式。 |
| `--canary-percent` | | `<1-100>` | `10` | `--strategy canary` のとき、最初にトラフィックを流す割合。 |
| `--timeout` | `-t` | `<DURATION>` | `10m` | デプロイ全体のタイムアウト（例: `30s`、`5m`、`1h`）。 |
| `--dry-run` | `-n` | | `false` | 実際には変更せず、実行予定の内容だけを表示します。 |
| `--yes` | `-y` | | `false` | 確認プロンプトを省略します。CI での利用を想定しています。 |
| `--no-rollback` | | | `false` | 失敗しても自動ロールバックを行いません。 |
| `--force` | `-f` | | `false` | デプロイロックや凍結期間を無視して実行します。権限が必要です。 |
| `--message` | `-m` | `<TEXT>` | なし | デプロイ履歴と通知に記録するメモ。 |
| `--wait` / `--no-wait` | | | `--wait` | ヘルスチェックの完了まで待つかどうか。 |
| `--output` | `-o` | `text` \| `json` | `text` | 出力形式。 |
| `--verbose` | `-v` | | `false` | 詳細なログを出力します。 |
| `--help` | `-h` | | | ヘルプを表示します。 |

## 環境変数

| 変数 | 説明 |
|---|---|
| `SHIPIT_TOKEN` | API 認証トークン。設定がない場合は `shipit login` で保存した認証情報を使います。 |
| `SHIPIT_ENV` | `--env` のデフォルト値を上書きします。 |

コマンドラインのオプションは、環境変数より優先されます。

## 使用例

ステージング環境へ `main` の最新版をデプロイする:

```sh
shipit deploy api
```

特定のタグを本番環境へデプロイする:

```sh
shipit deploy api --env production --ref v2.4.1
```

実行内容を事前に確認する（ドライラン）:

```sh
shipit deploy api --env production --ref v2.4.1 --dry-run
```

カナリア方式で、最初に 5% のトラフィックだけを流す:

```sh
shipit deploy web -e production -s canary --canary-percent 5
```

CI から確認なしで実行し、結果を JSON で受け取る:

```sh
shipit deploy worker -e production -r "$GIT_SHA" --yes --output json -m "CI build #$BUILD_ID"
```

ビルド済みのイメージを指定してデプロイする:

```sh
shipit deploy api -e staging --image registry.example.com/api:2024-11-01
```

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功。`--dry-run` の場合は、計画の作成に成功したことを示します。 |
| `1` | 一般的なエラー（想定外のエラー）。 |
| `2` | 引数またはオプションが不正（例: `--ref` と `--image` を同時に指定した）。 |
| `3` | 認証エラー、または権限不足。 |
| `4` | 事前チェックで失敗（デプロイロック中、凍結期間中、対象のリビジョンが見つからない、など）。 |
| `5` | デプロイに失敗し、自動ロールバックに成功した。 |
| `6` | デプロイに失敗し、ロールバックにも失敗した、または `--no-rollback` が指定されていた。**手動での対応が必要です。** |
| `7` | タイムアウト（`--timeout` を超えた）。 |
| `130` | ユーザーが中断した（Ctrl+C）、または確認プロンプトで拒否した。 |

## 関連項目

- `shipit rollback` — 直前のリリースに戻す
- `shipit status` — 環境ごとのデプロイ状況を表示する
- `shipit history` — デプロイ履歴を表示する
