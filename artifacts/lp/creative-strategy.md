# Phase 2: クリエイティブ戦略とコンバージョン設計 (`deslop`)

## 1. コアコンセプトの策定（3案の比較と選定）

`design-direction` スキルの原則に従い、3つの異なるクリエイティブ方向性を比較したうえで最適案を選定した。

| 案 | 名称 | 1行テーゼ | トレードオフ（捨てるもの） | 判定 |
|---|---|---|---|---|
| **A（採用）** | **The Redline Proofing Room（赤入れ校正室と決定論的ターミナルの融合）** | 文芸誌・学術校正刷りの静謐な紙面（Warm Archival Paper）の上に、決定論的CLI（Carbon Terminal）と朱色の校正赤入れ（Vermilion Redline）が交差するエディトリアル体験。 | 派手な3Dオブジェクトやネオングラデーションによる視覚的ハッタリを捨てる。 | **採用**：`deslop` の本質（「責任ある人間の著者が署名できる散文」×「Python標準ライブラリによる契約検査」）を視覚・体験の両面で最も強く体現する。 |
| B | Dark CLI Matrix（純粋な黒背景ターミナルUI） | 画面全体をモノスペースとターミナルウィンドウで構成する開発者特化LP。 | 長文のBefore/After比較や日本語散文の読みやすさ・組版の美しさが損なわれる。 | 不採用（コード・CLIセクションに部分採用） |
| C | Swiss Minimal SaaS Grid（白背景＋青アクセントのB2Bカードグリッド） | 清潔な白背景に均一な機能カードを並べる王道SaaSレイアウト。 | 「AIが生成したような無難なSaaS LP」に見えやすく、`deslop` が否定する均一リズム（`STR-06`/`DEN-08`）そのものになってしまう。 | 不採用 |

## 2. ブランドの形容詞と「絶対にやらないこと（Restraint）」

### 追求する4つの形容詞（Must Convey）
1. **Incisive（鋭利・的確）**: 曖昧な修飾語を削ぎ落とし、行・列・ルールIDで的確に射抜く。
2. **Editorial（編集室の品格）**: 散文の組版、文字詰め、余白、赤入れ記号（取消線・傍注・事実保護ハイライト）が機能美を持つ。
3. **Deterministic（決定論的・検証可能）**: 感覚論ではなく、`detect.py`・`preserve_check.py`・`contract_check.py` の終了コード `0` と SHA-256 で証明する。
4. **Unvarnished（虚飾を排した）**: ページ自身のコピーライティングにおいても、`deslop` が禁止するAI定型句（`革新的`、`シームレス`、`〜することが可能になります`、`単なる〜ではなく`）を一切使わない。

### 絶対に避ける2つの印象（Must Never Read As）
1. **紫〜青グラデーションとガラスモーフィズムを多用した量産型AIツールLP**
2. **「AIチェッカーを騙す（Undetectable AI）」系の怪しいステルスツール**

## 3. コアメッセージとコピーライティング方針

### ファーストビュー（Hero）のコピー設計
- **カテゴリバッジ**: `AGENT SKILL & DETERMINISTIC PROSE LINTER · JA / EN · PYTHON 3.10+ STDLIB`
- **メインヘッドライン**:
  **機械生成の文体を削り、書かれた事実だけを残す。**
- **サブコピー**:
  `deslop` は日本語・英語の Markdown と平文から、チャット応答の残骸、AI特有の過剰語彙、根拠のない数値、水増しされた段落構造を取り除くエージェントスキルです。原文にない事実は1文字も足さず、数値・URL・コードブロックの生存を契約検査（`contract_check.py`）で保証します。
- **メインCTA**: `ライブ検出器で試す`（`#live-detector` へスムーズスクロール＆エディタフォーカス）
- **サブCTA**: `make link で導入する`（`#install` のワンクリックコピー付き導入セクションへ移動）＋ `GitHub リポジトリ` / `ルール一覧（81種）`

### コピーライティングの鉄則（Self-Dogfooding 原則）
本LPの地の文（サンプル悪文として引用する箇所以外）は、**`deslop` 自身の `detect.py` ルールに1つも抵触しない文章**で執筆する。
- ❌ 禁止表現: `シームレスに`、`革新的な`、`最大限に引き出す`、`重要な役割を果たします`、`〜することが可能になります`、`単なる〜ではなく`、`さまざまな用途`、`いかがでしたか`
- ✅ 採用表現: 何を入力し、どのスクリプトが走り、何が削られ、何が保護されるかを主語と動詞で直接書く。

## 4. 訪問者の理想的な行動フローとセクション設計（全9セクション）

単調なカードグリッドの連続を避け、**「視覚的証拠（Hero赤入れ比較） → 自分で触る（Live Detector） → なぜ言い換えプロンプトではダメなのか（3層の解剖） → どう動くのか（6フェーズ＆契約検査） → ジャンル適応（10 Genres） → ルール辞典（81 Rules + 24 Perspectives） → 導入（Install & CLI）」**へと自然に納得が深まる情報設計とする。

| 順序 | セクションID | 役割とコンバージョン上の狙い | レイアウト・インタラクション表現 |
|---:|---|---|---|
| 1 | `#hero` | **Hero（第一印象と即座の価値証明）**: 3秒で「何をするツールか」「どれほど文章が引き締まるか」を視覚化する。 | 左カラムに明確な価値提案＋2つのCTA＋ワンライナーコピー (`make link`)、右カラムに実フィクスチャ (`examples/before.ja.md` → `after.ja.md`) の**対話型赤入れ校正ビュー（Before 30 hits / Redline Diff / After 0 hits 切替）**を配置。 |
| 2 | `#proof-strip` | **Quantitative Proof（リポジトリ実証指標）**: 架空の実績ではなく、コードベースとテストスイートが持つ検証可能な数値だけを示す。 | `81` 決定論的ルール / `24` 構造・内容観点 / `10` 文書ジャンル / `429` 回帰テスト / `0` 外部依存パッケージの5指標ストリップ。 |
| 3 | `#live-detector` | **Interactive Detector Sandbox（体験による確信）**: 訪問者が自分の手でサンプル文書や任意の文章を検査し、行・列・ルールID・密度メトリクス・書き換え結果を確認できる。 | 4つの実サンプル（日本語解説・英語ガイド・社内ブログ・英語LP）＋自由入力、10ジャンル切替、リアルタイム赤入れハイライト、検出ヒット一覧、密度メトリクスゲージ、`After` 比較タブ。 |
| 4 | `#three-layers` | **The Three Layers（なぜプロンプトだけでは消えないのか）**: 語彙の言い換えだけではAI臭が残る理由を「Content → Structure → Wording」の3層と4つの内容テスト（Information / Substitution / Reader / Support）で解き明かす。 | 非対称エディトリアルレイアウト。各層で実際に削除・書き換えられる具体文とルールIDを対比表示。 |
| 5 | `#pipeline` | **6-Phase Run Contract（事実を1つも捏造・喪失させない仕組み）**: 「AIに直させると数値やコードが壊れる」という最大の不安を払拭する。 | `INVENTORY → VOICE → DETECT → REWRITE ⇄ VERIFY → REPORT` の6フェーズ切替ステッパー。各フェーズの実行コマンドと生成ファイル（`snapshot.json`, `preserve.json`, `findings.json`, `report.md`）の実データを表示。 |
| 6 | `#genres` | **Genre-Aware Tuning（10の文書ジャンル適応）**: READMEの箇条書きやAPIリファレンスの太字、テンプレートの `[担当者名]` まで誤爆しない知性を示す。 | 10ジャンルのインタラクティブ・マトリクス。ジャンルを選択すると「残す慣習（Keep）」「削る要素（Remove）」「自動免除ルール・密度上限の変更値」が即座に切り替わる。 |
| 7 | `#rule-atlas` | **Rule & Perspective Atlas（全81ルール＋24観点の検索可能リファレンス）**: どのような根拠と粒度でAI文体を定義しているかを透明化する。 | カテゴリフィルタ（All / Artifact 9 / JA Lexical 33 / EN Lexical 27 / Content & Density 11 / Perspectives 24）＋キーワード検索付きのルール辞典。 |
| 8 | `#faq` | **Technical FAQ（導入前の疑問解消）**: AI検出器との関係、Git未管理ファイルの安全性、単体CLI実行、対応ホストに関する具体的な質問と回答。 | キーボード操作・アクセシビリティ対応のアコーディオン（初期状態で重要項目を展開可能）。 |
| 9 | `#install` | **Install & CLI Quickstart（最終コンバージョン導線）**: エージェントへの導入と単体CLI実行を1クリックで完了させる。 | ホスト別タブ（All Hosts / Claude Code / Codex / Antigravity / Standalone CLI）＋ワンクリックコピーボタン＋実際の終了コード仕様説明。 |
