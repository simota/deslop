# Phase 1: プロダクト徹底分析レポート (`deslop`)

## 1. プロダクトの概要と本質

`deslop` は、日本語・英語の Markdown およびプレーンテキスト文書から、**機械生成特有の文体・構造・空疎な主張（AIスロップ）を、原文にない事実を一切追加することなく除去するエージェントスキル（Claude Code / Codex / Antigravity 対応）および決定論的検出ツール群**である。

単なる「言い換えプロンプト」や「AIチェッカー回避ツール」ではない。`deslop` は以下の3層に対して、決定論的スクリプト（Python 3.10+ 標準ライブラリのみ）とエージェントの構造読解を組み合わせて推敲を行い、最終的に契約検査（`contract_check.py`）を通過するまで `REWRITE ⇄ VERIFY` を反復する。

1. **Content（内容層）**: 読者に新しい情報を与えない文（`CON-01`）、別の製品名に置き換えても成り立つ空疎な主張（`CON-07`）、出典のない統計値（`CNT-01` / `CON-03`）、架空のペルソナ例（`JA-32` / `EN-27` / `CON-04`）を、言い換えるのではなく**まず削除**する。
2. **Structure（構造層）**: 「本記事では〜を解説します」という予告開幕（`STR-01` / `JA-08`）、「## まとめ」による本文の反復（`STR-02` / `JA-09`）、無理やり3つに揃えた箇条書き（`STR-04` / `DEN-09`）、`〜とは？` 形式のSEO見出し（`STR-14` / `JA-17`）を解体し、散文または本来の構造へ戻す。
3. **Wording（語彙・表記層）**: チャット応答の残骸（`ART-01`〜`ART-09`：「承知しました」「参考になれば幸いです」「Certainly!」「oaicite」）、AI頻出語彙（`JA-01`〜`JA-33`、`EN-01`〜`EN-27`、`EMO-01`：「シームレス」「革新的」「〜と言っても過言ではありません」「〜することができます」「delve」「leverage」）、および文書全体の密度指標（`DEN-01`〜`DEN-10`：太字過多、ダッシュ過多、文末の連続、文長の均一性）を検出・解消する。

## 2. 9つの本質的問いへの回答

| # | 問い | 回答（リポジトリの実装に基づく根拠） |
|---|---|---|
| 1 | **何を実現するのか** | AIが下書きした文書やAI臭が残るドキュメントから、機械生成の痕跡（80の決定論的ルール＋24の内容・構造観点）をゼロにし、著者本来の文体（`voice`）と文書内の事実（数値・URL・コード）だけを厳密に残す。 |
| 2 | **誰のどんな課題を解決するのか** | Claude Code / Codex / Antigravity 等のコーディングエージェントで README、設計書（RFC/Spec）、APIリファレンス、技術記事、PR説明文、メール等を作成するエンジニア・テックライターが抱える「AIに書かせると水増しされた定型文になり、手で直すのに時間がかかる」「AIに推敲させると勝手に事実や数値を捏造・削除される」という課題を解決する。 |
| 3 | **なぜ使いたくなるのか** | 「AIっぽさを消して」と口頭で指示するだけでは再発する別種のAI語彙（`重要` → `肝心`、`leverage` → `utilize`）や事実の改変を、`detect.py`・`preserve_check.py`・`contract_check.py` が終了コード `0/1` で機械的に差し止めるため。 |
| 4 | **導入前と導入後で何が変わるのか** | 例（`examples/before.ja.md` → `examples/after.ja.md`）：30件のルール違反と3件の構造キューを含む396文字の冗長な解説記事が、必要な設定項目（`ttl_seconds = 300`, `max_entries = 10000`, TOMLブロック, 公式URL）を1つも失わずに105文字（−73%）の端正な技術文書へ収束する。 |
| 5 | **競合・既存手段との違いは何か** | ① **AI検出器回避（Undetectable AI等）ではない**：わざと誤字や砕けた表現を混ぜるのではなく、中身のない文を削り事実を残す。② **プロンプト単体ではない**：Python標準ライブラリ製の5つの検証スクリプトがSHA-256スナップショット、事実保存検査、契約検査を強制する。③ **ジャンル認識（10種）**：`readme`, `reference`, `tutorial`, `article`, `spec`, `pr`, `message`, `changelog`, `template`, `general` ごとに正当な慣習（APIリファレンスの太字パラメータ名やテンプレートの空欄など）を自動免除し、密度閾値を調整する。 |
| 6 | **最も魅力的な機能・体験は何か** | `detect.py` によるリアルタイムな赤入れ（行・列・ルールID・密度数値・構造キューの特定）と、`preserve_check.py` による「数値・URL・インラインコード・コードブロック・脚注が1つでも無断で消えたり増えたりしたら失敗する」事実保存保証。 |
| 7 | **価値を実感する瞬間はどこか** | 自分の `docs/` や `README.md` に `make detect TARGET=docs/` を流した瞬間に出る `path:line:col RULE text` の一覧を見たとき、そして書き換え後の `report.md` で「除去前の検出 → 除去後の未処理 0」「事実の捏造 0」を確認した瞬間。 |
| 8 | **目指す世界観は何か** | **「責任ある人間の著者が署名できる散文」**（*writing a careful human author would sign*）。装飾やハッタリを排し、言いたいことだけを正確に述べる編集室・校正刷り（Redline Proofing）の美学。 |
| 9 | **LP訪問者に最終的に取ってほしい行動** | ① ページ上のインタラクティブ検査器（Live Detector）で実際の検出精度を体験する、② `make link` コマンドをコピーして自分のエージェント環境（Claude Code / Codex / Antigravity）にシンボリックリンクを導入する、または `detect.py` を単体実行する。 |

## 3. ターゲットユーザーとペルソナ設計

### 主なターゲット層
1. **AIエージェント常用ソフトウェアエンジニア / OSSメンテナ**
   - Claude Code、Codex、Antigravity を日常的に使い、コードだけでなく `README.md`、設計ドキュメント（`spec`）、PR説明文（`pr`）、リリースノート（`changelog`）を生成・更新している。
2. **技術広報・Developer Relations・テックライター**
   - 技術ブログ（`article`）、チュートリアル（`tutorial`）、APIリファレンス（`reference`）の下書きにLLMを使うが、「本記事では〜を徹底解説します 🚀」「いかがでしたか？」といった生成臭や、翻訳調の日本語（`〜において`、`〜することが可能になります`）の赤入れに疲弊している。
3. **ドキュメント品質・CI管理を行うテックリード**
   - リポジトリ内のドキュメントに「未入力プレースホルダ（`[会社名]`、`2025-XX-XX`）」「チャットURLパラメータ（`utm_source=chatgpt.com`）」「出典なき改善率（`約30%向上`）」が混入するのをCI（`detect.py` の終了コード `0/1`）で防ぎたい。

### ユーザーの心理的障壁と解消策
| 心理的障壁・懸念 | リポジトリの事実に基づく解消策 |
|---|---|
| 「AIに文章を直させると、コードブロックや設定値、URLまで勝手に書き換えられるのでは？」 | `preserve_check.py` が原文スナップショット（`original/`）と作業コピーを比較し、数値（符号・指数・全角含む）・URL・リンク先・インラインコード・コードブロック・脚注の増減をすべて検出。未承認の変更があれば `contract_check.py` が失敗（Exit 1）する。コードブロックは絶対に編集しない。 |
| 「APIリファレンスの太字リストや、メールの『お気軽にお問い合わせください』まで機械的に消されたら困る」 | 10種類の文書ジャンル（`--genre`）が定義されており、`reference` では太字パラメータ名（`DEN-01`/`DEN-04`）を免除、`message` では返信への誘い（`JA-21`/`EN-20`）を免除、`template` では入力欄プレースホルダ（`ART-07`）を免除する。 |
| 「チームの文体（である調 / です・ます調、用語の英語表記など）が崩れるのでは？」 | `VOICE` フェーズで既存文書やスタイルガイドから3〜8個の文体ルール（文末、人称、英単語表記、中黒・長音記号など）を抽出し、`findings.json` に記録して遵守する。 |
| 「依存パッケージやAPIキーの設定が面倒では？」 | Python 3.10+ の標準ライブラリのみで動作し、`pip install` や外部パッケージは一切不要。`make link` 一発で `~/.claude/skills`、`~/.codex/skills`、`~/.gemini/antigravity-cli/skills` にシンボリックリンクされる。 |

## 4. 確認できた事実と厳守すべき境界（捏造の禁止）

リポジトリから確認できた正確な数値・仕様のみをLP全体で使用する。

- **対応言語**: 日本語（`ja`）および英語（`en`）の Markdown / プレーンテキスト
- **対応ホスト**: Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Antigravity (`~/.gemini/antigravity-cli/skills`)、およびプロジェクトローカル (`.claude/skills`)
- **決定論的ルール数**: `rules.json` 定義全 **81** ルール（README表記上は `80 rules + 24 perspectives`、`JA-33` 追加により実定義は81件）
  - `artifact`（チャット残骸）: **9** ルール（`ART-01`〜`ART-09`）
  - `lexical`（語彙・定型句・絵文字）: **61** ルール（英語 `EN-01`〜`EN-27` の27件、日本語 `JA-01`〜`JA-33` の33件、絵文字 `EMO-01` の1件）
  - `content`（無出典の統計主張）: **1** ルール（`CNT-01`）
  - `density`（文書密度指標）: **10** ルール（`DEN-01`〜`DEN-10`、最低400文字、見出し・リスト比率は1,500文字以上）
- **構造・内容の観点（Perspectives）**: 全 **24** 観点
  - 内容観点（Content）: **8** 観点（`CON-01`〜`CON-08`）
  - 構造観点（Structure）: **16** 観点（`STR-01`〜`STR-16`）
  - そのうち `detect.py`（`cues.py`）が文書形状から自動キュー出しする観点: **11** 種類（`STR-01`〜`STR-06`, `STR-11`, `STR-13`, `STR-14`, `STR-16`, `CON-05`）
- **対応ジャンル**: 全 **10** ジャンル（`general`, `readme`, `reference`, `tutorial`, `article`, `spec`, `pr`, `message`, `changelog`, `template`）
- **実行フェーズ**: 全 **6** フェーズ（`INVENTORY → VOICE → DETECT → REWRITE ⇄ VERIFY → REPORT`）
- **テストスイート**: オフライン回帰テスト **429** 件（`make check` で全件パス）、および10ジャンル **35** 文書のテストコーパス（`corpus/`）
- **ランタイム要件**: Python 3.10+ 標準ライブラリのみ（外部依存ゼロ）
- **典拠（`reference/patterns.md` に明記された情報源）**:
  - Wikipedia "Signs of AI writing"
  - PubMed 抄録の過剰語彙研究（Kobak et al. 2025, Juzek and Ward 2025）
  - tropes.fyi
  - 日本語AI文体分析（Zenn, note, aiproof）
