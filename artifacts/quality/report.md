# SQI: 改善前後の比較

基準・重み・測定条件は `README.md`（改善前に確定、コミット `5825e0c`）のとおりで、
改善後に変更していません。測定値は `baseline/` と `after/` にあり、
同じスクリプト（`measure/`）で取得しました。

## 改善前スコアの訂正

作業中に、改善前の状態にもあった問題を 4 件見落としていたことに気付きました。
基準は変えず、同じ基準で改善前の評点を付け直しました。
付け直した評点は、改善後の採点にも同じ厳しさで適用しています。

| 項目 | 確定時 | 訂正後 | 見落としていた根拠 |
|---|---:|---:|---|
| D1 責務分離 | 3 | 2 | ブラウザ用の代替検出器（`app.js` の `clientSideDetect`）が `detect.py` の判定を再実装している。静的ホスティングでは Python を動かせないために必要な重複だが、件数には数える（2 → 3 件） |
| D2 凝集度 | 4 | 2 | `common.py` が、Markdown のブロック解析、ファイル入出力、ジャンル判定、スナップショット読み込み、報告用のエスケープを一緒に持っている（1 → 2 モジュール） |
| D4 変更容易性 | 2 | 1 | 未検査の同期箇所に、README のフェーズ列とルール数、ジャンル説明の上限値、ヒーローの文字数表示が加わる（6 → 10 件） |
| U3 予測可能性 | 3 | 2 | ヒーローの「赤入れ検出 (30)」が英語サンプル（22 件）に切り替えても 30 のまま（3 → 4 件） |

## A. 改善サマリー

調査した領域は、スキルのスクリプト 9 本（依存グラフ、責務、例外処理、契約）、
`site/`（ランディングページ、ライブ検出器、ローカル API）、CI、Makefile、README と AGENTS.md です。

重要な問題と、その対応:

1. 導入コマンドの clone URL が存在しないリポジトリを指していた。主要タスクの T4 が失敗する状態だった。修正済み
2. 実行契約の表示が 6 フェーズで、SKILL.md の 8 フェーズと違っていた。REVIEW と SELECT を追加し、テストで一致を保つ
3. サイトの同梱データと表示中の数値が手作業の同期で、すでにずれていた（テスト数、文字数、ルール説明 2 件、免除理由の書式）。生成スクリプトと検査テストで解消した
4. `detect.py` が `preserve_check.py` の内部関数に依存していた。共有の Markdown 解析を `markdown_spans.py` へ移した
5. ローカル API が内部エラーを 400 と例外文で返し、負の長さを受けると待ち続けた。修正し、テストを追加した
6. タブがキーボードで操作できず（axe critical）、結果の行もマウスでしか開けなかった。共通の選択処理にまとめ、WAI-ARIA のタブパターンに合わせた
7. 初回表示でヒーローが後から埋まり、レイアウトがずれていた（CLS 0.13）。初期表示を HTML に含めた
8. 密度欄がジャンルに関係なく既定の上限を表示していた。`rules.json` とジャンルから導くようにした
9. 編集中の文章が、サンプルを切り替えると警告なしに消えた。確認を出すようにした

採用しなかった変更と理由:

| 候補 | 理由 |
|---|---|
| `common.py` の分割（Markdown のブロック解析を別モジュールへ） | 凝集度は上がるが、テストを含む多数の import を書き換える必要がある。移動先の名前の扱いも含めて、今回の検証範囲に対して変更の波及が大きい |
| `_` で始まるコンテナ関数（`_continue_containers` など）の公開名への変更 | 名前を変えるだけで挙動は変わらず、検証できる効果がない |
| ダークモード | 色トークンの全面的な追加とコントラストの再検証が必要で、デザイン上の判断も伴う。今回の非劣化を確かめられる範囲を超える |
| 入力ごとの API 呼び出しの間引き（debounce） | ローカルでは応答が速く、効果を測れない。体感の遅れを増やす可能性もある |
| `E741`／`B905`／`B023` の修正 | 意図的かどうかを判断する材料がなく、挙動を変える可能性がある |
| 境界を強制するテスト（例: `detect` が `preserve_check` を import しない） | 1 件の境界のためのテストで、現状では過剰と判断した |

## G. 残存リスクと未検証項目

- 実ユーザーテスト、スクリーンリーダーの実機確認、実ネットワークでの表示速度は測っていない。U1、U2、U6、U7 はこの範囲での評価
- `app.js` の挙動は CI で検査していない（Playwright と axe はリポジトリの依存にしていない）。`measure/` のスクリプトは手で実行する
- ヒーローの文字数表示（「396字 → 105字」「634 chars → 176」）は算出方法が分からず、検証も自動検査もできていない
- `GENRE_DETAILS` の keep／remove の文言、FAQ、各節の説明文は編集上の記述で、正しさは検査していない
- API 応答待ちの表示がない。遅いサーバーでは、前回の結果が一瞬残る
- ダークモードがない（`prefers-color-scheme: dark` でも明るい表示のまま）
- `common.py` の凝集度（D2）は改善の余地が残る
- 評点の多くは E2（再現可能な静的解析・テスト・スクリプト）で、V3、V7、U2 は E1（観察）のまま
