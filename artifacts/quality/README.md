# SQI: 品質評価の基準とベースライン

このディレクトリは、リポジトリの設計・アーキテクチャ・デザイン・UI/UX の品質を
同じ基準で改善前後に採点した記録です。この README は改善作業の前に確定し、
改善後に基準・重み・測定条件を変更していません。結果と比較は `report.md` にあります。

- 対象コミット（改善前）: `95efdfa`
- 測定スクリプト: `measure/arch.py`（依存構造）、`measure/perf.py`（性能）、`measure/ui.js`（UI、Playwright と axe-core 4.10.2）
- 改善前の測定値: `baseline/arch.json`、`baseline/perf.json`、`baseline/ui.json`

SQI はこのリポジトリ専用のルーブリックによる評価で、物理量ではありません。
実ユーザーによるテストは行っていません。UX 項目の「タスク成功」は、筆者（AI）が
スクリプトと手作業で手順をたどった結果であり、ユーザーテストの代わりにはなりません。

## 対象

| 領域 | 対象 | 対象外 |
|---|---|---|
| DQI・AQI | `skills/deslop/scripts/*.py`、`site/serve.py`、`site/app.js`、`site/data.js`、`Makefile`、CI | `artifacts/promo/source`（動画制作用の使い捨てスクリプト）、`corpus/`・`examples/`（テスト入力） |
| VQI・UXQI | `site/`（ランディングページとライブ検出器）を `make serve` で表示したもの | CLI の端末出力（画面ではないため。エラー文と終了コードは DQI の契約で扱う） |

重みは 4 領域とも 0.25 で、作業前に固定した。

**SQI = 0.25 × DQI + 0.25 × AQI + 0.25 × VQI + 0.25 × UXQI**、
**領域スコア = Σ（重み × 評点 ÷ 5）**。

## 測定条件（固定）

- ビューポート: 320×700、390×844、768×1024、1440×900（ライト）、1440×900（`prefers-color-scheme: dark`）
- データ: 同梱サンプル（`examples/before.*.md`、`corpus/article/code-review-ja.md`、`corpus/reference/deploy-cli-reference-ja.md`）
- サーバー: `python3 site/serve.py --port 8765`（ローカル、ネットワーク遅延なし）
- 言語: 日本語ページ（`lang="ja"`）
- 権限: なし（公開ページ）

## 主要タスク（UX、開始条件と成功条件）

| ID | タスク | 開始 | 成功条件 |
|---|---|---|---|
| T1 | サンプルの検出結果を見る | ページを開く | 検出器の結果一覧と本文の赤入れが表示され、結果の行から本文の該当行へ移動できる |
| T2 | 自分の文章を検査する | 「Markdownを自由編集」 | 入力した文章のヒットが表示される |
| T3 | 実行の流れを理解する | 「実行契約」節 | ページに出ているフェーズが SKILL.md の Phases と一致する |
| T4 | 導入する | 「導入」節 | 表示されたコマンドをコピーして実行すると、このリポジトリを取得できる |

## 証拠レベル

E0 未検証 / E1 コードや画面の観察 / E2 再現可能な静的解析・自動テスト・スクリプト化した手順 / E3 実測または独立した複数の根拠。
E0 の項目には点を付けない。

## 採用条件

1. `make check` がすべて成功し、既存テストを無効化・削除していない
2. CLI・API・`findings.json` の入出力と終了コードが変わらない
3. 固定条件で axe の違反、横スクロール、コンソールエラーが増えない
4. コーパス走査の中央値が誤差（±10%）を超えて悪化しない
5. 改善の根拠が測定値またはテストで示せる
